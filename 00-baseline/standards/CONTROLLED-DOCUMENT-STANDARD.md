A Controlled Document establishes, governs, reviews, or certifies architecture. It requires immutable identity, declared authority, explicit dependencies, semantic version, lifecycle state, traceability, review evidence, and controlled change. Only Baselined documents are normative. Informal notes and generated outputs are non-authoritative unless promoted through lifecycle governance.

## Document control

This controlled document is immutable in this release. Changes require the approved ADR and change-control process. Cross-references use Constitutional Document IDs; filenames are non-authoritative.
