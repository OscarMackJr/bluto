## Decision

Bluto will use immutable, versioned ADRs for material architecture, contract, security, engineering, test, operational, and AI-factory decisions. An ADR is required for new authority, changed invariant, new technology class, breaking contract, trust-boundary change, or exception becoming permanent.

Statuses are Proposed, Under Review, Approved, Implemented, Superseded, Withdrawn, and Archived. An approved ADR is never edited to reverse history; a successor ADR supersedes it. Approval requires architecture owner, impacted specialists, evidence, alternatives, consequences, and cross-stream impact.

## Document control

This controlled document is immutable in this release. Changes require the approved ADR and change-control process. Cross-references use Constitutional Document IDs; filenames are non-authoritative.
